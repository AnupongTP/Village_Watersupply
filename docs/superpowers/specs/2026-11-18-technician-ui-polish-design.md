# หน้าช่าง/หน้าสาธารณะ: เก็บงานหน้าตา + แผนที่ในหน้าจัดการ (งาน A) — Design

วันที่: 2026-11-18 · สถานะ: รอเจ้าของงานอนุมัติ · ยังไม่ commit · งาน B (สวิตช์แสดง/ไม่แสดง + นอกเขตพะเยา) แยกเป็นเอกสารภายหลัง

## เจตนา
เจ้าของงานลองใช้แล้วพบว่า UI ยัง "ไม่เหมือน/ไม่เสร็จ" 4 จุด และหน้าจัดการ (ที่ช่าง/ผู้ดูแลใช้ค้นแล้วแก้ข้อมูลหลังลงพื้นที่) ยังต้องเด้งไปหน้าแรกเพื่อดูแผนที่ เป้าหมายคือให้ทั้งหน้าดูเป็นชิ้นเดียวกับ Reference และทำงานจัดการจบในหน้าเดียว

## เป้าหมาย (สิ่งที่เจ้าของงานพูด)
1. **ปุ่มรีเฟรชเข้าที่** — มือถือหน้าสาธารณะ: ปุ่มหล่นไปบรรทัดใหม่ใต้เมนู; คอมหน้าช่าง: ปุ่มถูกบีบใน header ม่วง
2. **ระยะขอบ** — เนื้อหาในหน้าจัดการ (เช่น หัวข้อ "ผู้ดูแลระบบ / บัญชีช่างเทคนิค", รายการระบบ) ชิดขอบ ไม่อยู่ในการ์ดแบบ Reference
3. **กล่องแจ้งเตือนใหญ่** "ระบบนี้ไม่อยู่ในขอบเขตแผนที่ปัจจุบัน" — เป็นผลจากปุ่มแผนที่เรียกแผนที่ UI เก่าที่ไม่ได้เปิดใช้ (`handleSystemAction('map')` → `VWSTechnicianMap.focus` ล้มเหลว → `toast(...,'warning')`) และกล่องแจ้งเตือนยังเป็นสไตล์เดิม
4. **แผนที่ในหน้าจัดการ (เลือกแบบ ก + A1)** — แผนที่อยู่เหนือรายการระบบตลอด; กดปุ่มแผนที่ในแถว → เลื่อนขึ้นและซูมไปหมุดนั้นในหน้าเดียวกัน (ไม่เด้งไปหน้าแรก); จาก popup หมุดกดเปิดรายละเอียด/แก้ไขได้

## ไม่ใช่เป้าหมาย / ห้าม
- ไม่แตะ Backend/SQL/Auth/สิทธิ์อำเภอ/R5.1 (งาน B แยก)
- ไม่เปลี่ยนเนื้อหา/พฤติกรรมของหน้า บทสรุปผู้บริหาร/รายละเอียดข้อมูล (นอกจากตำแหน่งปุ่มรีเฟรชใน header)
- ไม่เพิ่มความสามารถจัดการใหม่ — ปุ่มใน popup เรียก action เดิม (`openSystem(id)` / `handleSystemAction('edit',id)`) ซึ่งตรวจสิทธิ์ `UPDATE_SYSTEM` + `managementMutable` เดิม
- Anti-goal: ช่างเห็นหมุดนอกอำเภอ; แผนที่ค้าง/ซ้อนหลัง logout-login; คำเตือนผิด ๆ ยังเด้ง

## ข้อจำกัด
- แก้ใน Candidate ผ่าน generator (`output/ui-ux-preview/execution/build-reference-*.py`, assert anchor, regen idempotent ด้วย `output/ui-ux-preview/gemini-review/manage-view/regen.sh`) และ bridge เขียนมือ `technician/assets/reference-technician.js`; ซิงก์ root หลัง test ผ่าน (สำรองก่อนทับ)
- `technician.js` ใน root เป็นไฟล์ที่ generator สร้างจาก `promotion-backup-2026-11-17/root-before/` — แก้ผ่าน generator เท่านั้น
- ไม่เรียก API จริง; ไม่ commit/push/deploy จนกว่าสั่ง; Node ในเครื่อง 24 (CI 22)

## Approaches (แผนที่ในหน้าจัดการ)
| ทาง | สรุป | ข้อแลก |
|---|---|---|
| **A1 (เลือก)** | แผนที่ Leaflet ใหม่ของหน้าจัดการ สร้างใน bridge ใช้หน้าตาหมุด/กลุ่มหมุดแบบหน้าแรก หมุดตามตัวกรองรายการ | ตรงงานจริง แยกจากหน้าแรก ไม่รื้อโค้ดแผนที่ Reference; ต้องดึงตัวช่วยวาดหมุดจาก view มาใช้ร่วม |
| A2 | ย้ายแผนที่หน้าแรกมาใช้ซ้ำ | โค้ดน้อย แต่หมุดตามตัวกรองหน้าแรก ไม่ตามรายการ และย้าย DOM ไปมาเปราะ |
| ข (ไม่เลือก) | แผนที่เป็นหน้าต่างเมื่อกดปุ่ม | รายการอยู่บนสุด แต่ไม่เห็นภาพรวม — เจ้าของงานเลือก ก |

## ส่วนที่ตัดสินแล้ว
- แผนที่อยู่เหนือรายการ (แบบ ก); มือถือแผนที่เตี้ยลง
- หมุดตามตัวกรองของรายการ (คำค้น + ทั้งหมด/เฝ้าระวัง) — ข้อเสนอ Claude ที่เจ้าของงานไม่ได้คัดค้าน
- ระบบไม่มีพิกัด: ปุ่มแผนที่ในแถวเป็นสีเทาตามเดิม

## การตัดสินใจของผู้ออกแบบ (Claude) — ตรวจได้
1. **ปุ่มรีเฟรช**: คอม — อยู่ขวาบน header ม่วงคู่ปุ่มผู้ใช้ ขนาด/ฟอนต์เท่าปุ่มผู้ใช้ ไม่ถูกตัดข้อความ; มือถือ (≤767px) — เป็นปุ่มไอคอน (มี `aria-label="รีเฟรชข้อมูล"`) อยู่บรรทัดเดียวกับชื่อ ไม่ขึ้นบรรทัดใหม่; ใช้ทั้งหน้าสาธารณะ (`#btnRefresh .reference-refresh` สร้างใน `assets/js/reference-start.js`) และหน้าช่าง (`#refreshButton` ใน `.topbar-actions`)
2. **การ์ด**: ทุก section ในหน้าจัดการ (`#watchlist` ส่วนหัว/ค้นหา/ผลรายการ, `#techniciansPanel`, `#historyPanel` เมื่อเปิดจากปุ่มดูประวัติ) อยู่ในการ์ดพื้นขาว ขอบมน ~16px เส้น `#e4e0fb` เงาอ่อน ระยะในการ์ด ~20–24px (มือถือ ~14px); ขอบซ้ายขวาของหน้าเท่ากับหน้าบทสรุปผู้บริหาร
3. **กล่องแจ้งเตือน (toast)**: ปรับ `notify()` ของ `technician-ui.js` ผ่าน CSS ให้เป็นกล่องเล็กมุมจอ โทน Reference (ตัวอักษร ~14px ไอคอนเล็ก) — ไม่เปลี่ยนข้อความ/จังหวะเวลา
4. **แผนที่ในหน้าจัดการ (A1)**:
   - อยู่ใน `#view-manage` เหนือ `#manageListSlot` เฉพาะแท็บรายการ (ซ่อนในแท็บบัญชีช่าง); สูง ~420px คอม / ~260px มือถือ; มีปุ่มขยายเต็มจอแบบหน้าแรก (ถ้าทำได้ด้วยตัวช่วยเดิม)
   - ข้อมูลหมุด = `state.filteredSystems` ของ `technician.js` (ซึ่งผ่านการจำกัดอำเภอจาก backend แล้ว) เฉพาะที่มีพิกัดถูกต้อง; อัปเดตเมื่อรายการกรองใหม่ (hook จาก `applyFilters`/`renderSystemsTable` ผ่าน generator patch เรียก bridge)
   - หน้าตาหมุด/กลุ่มหมุด/popup ใช้ตัวช่วยของ Reference view (เปิด API ใหม่จาก `VWSReferenceView.mount()` เช่น ฟังก์ชันสร้าง icon และ popup) แทนการคัดลอกโค้ด
   - popup: ชื่อระบบ/หมู่บ้าน/สถานะ + ปุ่ม "รายละเอียด" (`openSystem(id)`) และ "แก้ไข" (เฉพาะมีสิทธิ์และ mutable)
   - ปุ่มแผนที่ในแถว: เมื่อ bridge มีแผนที่หน้าจัดการ → `focusManageMap(id)` (เลื่อนขึ้น ซูม เปิด popup) แทน `navigateToSection('map-section')`; ไม่มีการเรียก `toast` คำเตือนผิด ๆ อีก; ถ้าหมุดไม่อยู่ในตัวกรองปัจจุบัน → แจ้งเตือนสั้นข้อความใหม่ "ระบบนี้ถูกกรองออกจากรายการปัจจุบัน"
   - logout/destroy: ลบแผนที่ (`map.remove()`) และ listener ทั้งหมด; login ใหม่สร้างใหม่ตามสิทธิ์ผู้ใช้ใหม่
   - หน้าจัดการต้องยังผ่าน a11y (ปุ่มแผนที่มีชื่อ, แผนที่ไม่ดักคีย์บอร์ดจนออกไม่ได้)

## ข้อเท็จจริงจากโปรเจกต์ (ตอบคำถาม builder check)
- `state` ใน `technician.js` เป็นตัวแปรภายใน closure — ส่งข้อมูลให้ bridge ด้วย generator patch ที่ปลาย `renderSystemsTable()` (ยังไม่มี patch อื่นที่จุดนี้) เรียก `window.VWSReferenceTechnician?.syncManageMap?.(state.filteredSystems)`; anchor ต้องมี `assert`
- หน้าช่างโหลด Leaflet, `markercluster.js`, `reference-model.js`, `reference-view.js` อยู่แล้ว (generator ฉีด script) และ mount `VWSReferenceView` ใน `#referenceDashboard` — bridge ใช้ API ที่ view คืนมาได้
- สิทธิ์ใน popup: `technician.js` รู้ `hasPermission()`/`managementMutable` — ให้ `technician.js` ส่ง callback เพิ่มตอนเรียก `VWSReferenceTechnician.render(...)` (เช่น `onEditSystem`, `canEditSystem(system)`) ผ่าน generator patch; bridge ไม่ตัดสินสิทธิ์เอง
- `assets/js/reference-start.js` (สร้าง `#btnRefresh` หน้าสาธารณะ) ไม่ได้มาจาก generator — แก้ไฟล์ใน Candidate โดยตรง; CSS ปุ่มอยู่ใน `build-reference-view.py` (บล็อก `.reference-refresh`)
- ลำดับงาน: แก้ generator/ไฟล์เขียนมือใน Candidate → regen 2 รอบ → test บน Candidate → สำรองไฟล์ root → คัดลอกเฉพาะไฟล์ที่ต่าง → test บน root

## การตัดสินใจเพิ่มเติมของ Claude (จาก builder check)
- หมุด = **ทั้งชุดที่กรองแล้ว** (`state.filteredSystems`) ไม่ใช่เฉพาะหน้าปัจจุบันของตาราง (ตารางแบ่งหน้า 50 แถว)
- toast: กว้าง ≤ 360px (คอม) / ≤ ความกว้างจอ − 32px (มือถือ), สูง ≤ 96px สำหรับข้อความบรรทัดเดียว, ตัวอักษร 14px

## การทดสอบ / เกณฑ์รับ
- test ใหม่ทุกเป้าหมาย (RED ก่อน): ปุ่มรีเฟรชไม่ล้น/ไม่ตัดข้อความที่ 1440 และ 390 ทั้งสองหน้า; การ์ดมีระยะขอบ (bounding box ของเนื้อหาห่างขอบการ์ด ≥ 14px); toast ใหม่ขนาดไม่เกินค่าที่กำหนด; แผนที่หน้าจัดการแสดงหมุดเท่าจำนวนระบบที่มีพิกัดในรายการ, ค้นหาแล้วหมุดลดตาม, ปุ่มแผนที่ในแถวไม่เปลี่ยน view และเปิด popup ของระบบนั้น, popup "แก้ไข" เปิด `#editDialog`, ไม่มีสิทธิ์ → ไม่มีปุ่มแก้ไขใน popup, ช่างอำเภอเห็นเฉพาะหมุดอำเภอตน, logout→login ไม่มีแผนที่ซ้อน
- test เดิมที่ผูกกับพฤติกรรมปุ่มแผนที่เดิม (ไป `map-section`) ปรับตามพฤติกรรมใหม่โดยคง assertion เรื่องสิทธิ์/ไม่ยิง mutation
- เกณฑ์: E2E chromium-desktop ผ่านทั้งหมด (ยกเว้น real-api skip), Unit/static QA ผ่าน ทั้ง Candidate และ root

## เหลือให้ผู้สร้างตัดสินใจ
- ค่าระยะ/สี/เงาละเอียดภายใต้โทน Reference; ชื่อฟังก์ชัน API ที่เปิดจาก view; วิธี hook ข้อมูลรายการที่ patch น้อยที่สุด
